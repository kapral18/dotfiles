# Skills

Skills live in `home/exact_dot_agents/exact_skills/exact_k-<name>/` and deploy to `~/.agents/skills/k-<name>/SKILL.md`.
Claude Code, Pi, OMP, Codex, and OpenCode read the same tree. A model-invoked skill loads when its description matches the request. Manual skills require explicit invocation or an authorized handoff; reading their files alone does not authorize their workflows.

Skills provide task procedures. The global operating rules govern delegation, approvals, verification, and memory writes.

## README writing

`k-readme` is model-invoked for README creation, edits, and reviews. `k-code-quality` also loads it when a repository task touches a README.
It applies [ReadmeRoast](https://github.com/princejain756/readmeroast) to an existing local file after drafting, then checks each finding against the project and the requested scope.
Scores are advisory: factual accuracy and useful examples matter more than reaching 100. Curated lists and internal READMEs do not need artificial install or screenshot sections.

The CLI is pinned in the [pnpm package list](../../../home/readonly_dot_default-pnpm-pkgs) and installed through the [pnpm package workflow](../core/packages/pnpm.md).
The skill checks that the file exists before invoking the CLI, preventing an already-missing path from reaching its GitHub mode.
External URLs and heading anchors are outside the CLI's link check. If the binary is unavailable, the skill uses its rubric without claiming a score.

## Anti-slop writing and UI

`k-anti-slop` covers all six [antislop](https://github.com/miqdadbadjuber/anti-slop) domains and adds local guidance for technical documentation, interface copy, data displays, and localization.
Its nine references load by the requested change; a narrow edit does not load every category present in the surrounding artifact.
`k-code-quality` loads it for every edit or review, so the shared reviewer prompt gets it on every review; `k-code-quality-web`, `k-communication`, `k-readme`, and generated-content work in `k-artifact` route matching work to it. It preserves facts, intended voice, and design direction; existing SOP verification and approval rules remain authoritative.
The bundled Python contrast calculator runs locally without an MCP server. See the [inspection, coverage, and adoption decisions](anti-slop.md).

## Review and verification

Engineering reviews share a mandatory [adversarial stance](../../../home/exact_dot_agents/exact_skills/exact_k-review/exact_references/readonly_adversarial_stance.md): an AI-skeptical senior engineer seeking substantive failures beneath polished work. It adds scrutiny of necessity, complete outcomes, boundaries, assurance, and product quality. Main, light, direct mode/fix reviews, code-quality reviews, and fresh subagent reviewers load the same source. Each workflow retains its scope, judgment gates, authorship, checks, severity/reporting rules, and review/fix loop; the persona grants no additional actions.

Prefer the smallest in-scope design that rules out the error class in application logic and data. Tests protect its observable invariant; see the [global rules](../../../home/readonly_AGENTS.md#3-work-loop) and [design principles](../../../home/exact_dot_agents/exact_skills/exact_k-codebase-design/readonly_SKILL.md#principles).

Comments retain required directives or critical non-obvious constraints. Material implementation changes need durable behavioral coverage: reuse existing tests and add only missing protection. Static checks and disposable probes do not replace it. The [comment](../../../home/exact_dot_agents/exact_skills/exact_k-anti-slop/exact_references/readonly_comments.md) and [test](../../../home/exact_dot_agents/exact_skills/exact_k-code-quality-tests/readonly_SKILL.md) guidance define case selection, independent oracles, and removal of redundancy.

After a prototype question is settled, record its verdict in the task record and delete or absorb the prototype within authorized scope. Absorbed material behavior needs the same durable coverage; scheduled cleanup is not completion.

`k-review` handles local changes, PRs, feedback, and plans. Verify freezes scope and acceptance, launches two fresh reviewers, and fixes supported findings through unbounded rounds. Narrowed and fix-diff reviews do not replace the closing whole-scope round. The loop ends with no new supported medium-or-higher finding and its low findings fixed; recurring-cause stopping rules remain with the [fix procedure](../../../home/exact_dot_agents/exact_skills/exact_k-review/exact_references/readonly_review_fixes.md).

The [review skill](../../../home/exact_dot_agents/exact_skills/exact_k-review/readonly_SKILL.md) defines exact targeting, evidence, baseline, and reporting requirements. `k-light-review` covers small, self-authored, low-risk changes inline; both routes use `k-code-quality` and the relevant secondary guidance.

Review targets and the Verify workflow are separate choices. Local fixes follow the canonical authorship rules, including explicit requests to fix another author's work.

[`k-adversarial-review`](../../../home/exact_dot_agents/exact_skills/exact_k-adversarial-review/readonly_SKILL.md) keeps the separate holistic pre-publication workflow, including unchanged repositories, with that same stance. Its [six audit lenses](../../../home/exact_dot_agents/exact_skills/exact_k-adversarial-review/exact_references/readonly_audit-lenses.md) cover complete workflows and trust boundaries. Each finding requires a trigger, consequence, source evidence, attempted refutation, and smallest remedy. Suspected AI authorship and aesthetic taste do not establish defects.

Invoke it with: “Use k-adversarial-review to critique this entire solution before I make the repo public.” The audit is read-only; fixes require an explicit request. Verification uses source, static checks, and isolated simulations. It never runs integration, e2e, smoke, browser, live-service, or model evaluations. Missing rendered/deployment evidence and unexamined surfaces remain gaps. It complements `k-review`'s change verification and cannot certify a release secure.

[`k-communication`](../../../home/exact_dot_agents/exact_skills/exact_k-communication/readonly_SKILL.md) preserves relevant domain facts while excluding session provenance. It keeps related facts together and asks a closing question only when the recipient has something to decide or do.

Review queues reuse verified evidence only while its source and check inputs still match the saved snapshot, including local uncommitted and untracked files. Changed inputs refresh only the affected evidence and checks. A saved PR discussion must have been read completely before it can support a conclusion.

`k-diagnosing-bugs` puts an unresolved runtime criterion under `Open:` with the missing evidence or check as its blocker. `k-code-quality-web` reports static evidence under `Checked:` and claims requiring a live check under `Open:`. The evidence ledger excludes quoted and fenced examples, including fences inside lists, from report-citation checks.
